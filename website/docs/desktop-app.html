The desktop app

The macOS and Windows apps let you view meshes, set up a project, run the pipeline, and inspect the results in one place. Once installed, everything runs offline.

Written for version 2.0. The current download is v1.1.0, so a few things may look different in your copy.

1. Install the app

  • macOS: Apple Silicon, macOS 13 or later. Open the DMG and move Pinna2HRTF to Applications. The published DMG is ad-hoc signed and not notarized. If macOS blocks the first launch, choose Open Anyway in System Settings → Privacy & Security.
  • Windows: x64, Windows 10 version 2004 or later, or Windows 11. Windows ARM has not been tested. The installer is not digitally signed.

The desktop app includes Python, the inference models, and simulation tools. You do not need to install Python, Blender, or uv separately.

2. Create a project

  1. Create a project or import an existing project folder.
  2. Choose a project save location and add the left ear, right ear, or both. You can also enable full-head scan preparation; see the scan preparation guide.
  3. Use sidebar folders to organize projects. You can move projects between folders or duplicate them with their results. Removing a folder returns its projects to the main list. When removing a project, check the confirmation: the app may offer to move its folder to Trash or the Recycle Bin. Imported and protected folders remain on disk.

Projects and app settings live in different places. Outputs go to your project folder. App preferences, cached resources, and the project registry are stored elsewhere.

For detailed illustrated workflows, see manual PPM fitting and simulation and results.

3. Check the inputs

Mesh2PPM inference is optional and off by default. When enabled, it predicts a refined ear surface from the input mesh. Preprocessing uses the original mesh unless Use predictions for preprocessing is enabled. You can inspect the mesh in the viewer before continuing.

Project settings include the evaluation grid, ear distance and mesh parameters, frequency range, source setup, and optional scan-preparation controls. The run panel controls available stages and local NumCalc resource limits.

4. Prepare, solve, and export

  1. Use Scan Preparation if your project starts with a full-head scan.
  2. Mesh2PPM Inference (optional) predicts a refined ear surface.
  3. Preprocessing creates the simulation project geometry and setup files.
  4. NumCalc computes the acoustic field; local runs can limit parallel instances, CPU load, and memory where supported.
  5. SOFA export and postprocessing save the acoustic results.

Use Preview to inspect available meshes and plots. The live log reports stage activity; the technical log contains lower-level details. For microphone placement, see Simulation and results.

5. Keep and manage results

Generated inference, prepared-ear, simulation, and SOFA results are stored with the project. Reset Outputs deletes generated outputs. It keeps configured inputs, saved ear edits, scan alignments, manual PPM fits, and their Blender files. Back up results you need first.

Choose output processing

Resampling changes the HRIR sample rate. Spatial HRTF upsampling adds source directions by interpolating between the simulated directions; it does not change the sample rate or HRIR length. Upsampled files are saved separately in Upsampled/, and the original exports are kept.

Spatially upsampled HRIRs keep the level of the exported HRIRs. The optional frontal normalization (off by default) replaces that level with a −40 dB frontal reference. It is independent of the postprocessing level offset.

Troubleshooting

Prepared ears look misplaced or incomplete
Check scan orientation, selected sides, crop rotation, and crop placement. Review the ear meshes before continuing to preprocessing.
The pipeline is waiting for an ear review
If Require ear review before continuing is enabled, open each selected ear in the editor and use Save Reviewed Ear.
A stage reports an error
Read the technical log for the failing stage and check the configured input paths. Keep the log and configuration when reporting the problem.
No SOFA results are available
Confirm that NumCalc completed and that export and postprocessing ran. A prepared simulation project alone does not contain the final acoustic results.
